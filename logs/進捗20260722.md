# 進捗記録 2026/07/22

## 今日の目標

Reactで作成したフロントエンドと、Spring Bootで作成したバックエンドをAPI通信で接続する。

## 実施内容

### 1. APIの返却データをReactの型に合わせた

Spring Bootの`MissionController`が返すJSONの項目名を、React側の`Mission`型に合わせて修正した。

主な項目は以下のとおり。

- `id`
- `title`
- `category`
- `rewardExp`
- `completed`

APIへ直接アクセスし、想定どおりのJSONが返されることを確認した。

### 2. CORS設定を追加した

Spring Boot側の`MissionController`へ、以下の設定を追加した。

```java
@CrossOrigin(origins = "http://localhost:5173")
```

これにより、`localhost:5173`で動作するReactから、`localhost:8080`のSpring Boot APIへアクセスできるようにした。

### 3. ReactからAPIを呼び出した

Reactの`App.tsx`へ、`useEffect`と`fetch`を使用したAPI取得処理を追加した。

画面の初回表示時に、以下のAPIへGETリクエストを送信する。

```text
http://localhost:8080/api/missions
```

取得したJSONを`Mission[]`として受け取り、`setMissions(data)`でstateへ反映した。

### 4. APIから取得したミッションを画面へ表示した

Spring Boot側で用意した以下のミッションが、Reactのミッション一覧へ表示されることを確認した。

```text
Spring Boot APIを作成する
```

これにより、以下の一連の流れが動作するようになった。

1. Reactの画面を開く
2. `useEffect`がAPIを呼び出す
3. Spring BootがJSONを返す
4. ReactがJSONをstateへ保存する
5. stateの更新により画面が再表示される

### 5. API取得時のエラー処理を追加した

API通信部分へ`try...catch`を追加した。

また、`response.ok`を確認し、HTTPステータスが正常でない場合はエラーとして扱うようにした。

通信に失敗した場合は、ブラウザのConsoleへエラー内容を出力する。

### 6. 動作確認とビルド確認を行った

以下を確認した。

- Spring BootのAPIがJSONを返す
- ReactからAPIのデータを取得できる
- CORSエラーが発生しない
- APIから取得したミッションが画面へ表示される
- ブラウザのConsoleにエラーがない
- VS Code上のエラーと警告が0件
- `npm run build`が正常終了する

## 学んだこと

### APIのデータ形式はフロントエンドと揃える必要がある

バックエンドの`exp`とフロントエンドの`rewardExp`のように項目名が異なる場合、自動的には同じデータとして扱われない。

APIが返す項目名やデータ型を、フロントエンドとの共通ルールとして揃える必要がある。

### CORSについて

同じPC上で動作していても、ポート番号が異なる場合は別の接続元として扱われる。

Spring Boot側でReactからのアクセスを許可することで、ブラウザからAPI通信できるようになる。

### `useEffect`による初期取得

依存配列を空にした`useEffect`は、画面の初回表示時にAPIからデータを取得する用途で使用できる。

```tsx
useEffect(() => {
  // 初回表示時の処理
}, [])
```

### state更新による再表示

APIから取得したデータを`setMissions()`でstateへ保存すると、Reactが変更を検知して画面を自動的に再表示する。

### API通信のエラー処理

`response.ok`では、404や500などのHTTPエラーを確認できる。

`try...catch`では、バックエンドが停止している場合などの通信エラーも処理できる。

## 現在の注意点

現在実装されているのは、ミッション一覧を取得するGET通信のみ。

APIのミッションはJavaコード内に直接記述されており、データベースには保存されていない。

また、画面上でミッションを追加・編集・削除してもバックエンドには反映されないため、画面を再読み込みするとAPIのデータで再び上書きされる。
